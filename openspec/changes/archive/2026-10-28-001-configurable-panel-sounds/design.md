# Design: Configurable Panel Opening Sounds

## Context
Smack v0.2.0 added a synthesized audio effect to panel opening animations in `PanelController.open()`, generated by `SmackSound.swift`. The audio is an in-memory procedural WAV calculation creating a "smack" physical impact sound. Currently, this sound cannot be disabled or changed by the user.

## Goals / Non-Goals
- Goals:
  - Add a `PanelSound` enum representing `.none` (mute), `.smack` (custom procedural WAV), and macOS system alert sounds (`.pop`, `.tink`, `.ping`, `.blow`, `.bottle`, `.frog`, `.funk`, `.glass`, `.hero`, `.morse`, `.purr`, `.sosumi`, `.submarine`, `.basso`).
  - Store the selected sound preference in `CollectionSettings.panelSound` with automatic fallback to `.smack` when missing or corrupted.
  - Expose a clean, intuitive Picker in the "Panel" card of `SettingsView`.
  - Update `SmackSound` and `PanelController` to execute audio playback based on the user's configured preference.
- Non-Goals:
  - Custom audio file loading from disk or external URLs (avoids security/sandboxing complexities).
  - Volume slider controls (system alert volume and existing balanced 0.55 level are sufficient and keep the UI uncluttered, adhering to KISS).

## Decisions
- Choice of Audio Framework: Continue using AppKit `NSSound` instead of introducing `AVFoundation`. Rationale: `NSSound` is lightweight, already integrated, supports in-memory WAV data for `.smack`, and natively resolves macOS system sound names via `NSSound(named:)`.
- UI Placement: Place the Sound selector in the `Panel` settings card alongside other panel trigger options ("Open with", "Hover delay"). Rationale: The sound directly corresponds to the panel open action.
- Backward Compatibility: `CollectionSettings.init(from decoder:)` checks for the presence of `panelSound` and safely defaults to `.smack` if the key is absent or contains an unrecognized string.

## Risks / Trade-offs
- Risk: Loading `NSSound(named:)` for an unsupported system sound name could return nil. -> Mitigation: Optional chaining (`sound?.play()`) and silent recovery ensure zero crashes.
- Risk: Legacy settings serialization failure. -> Mitigation: Explicit migration test verifying legacy JSON retains default sound without throwing.

## Migration Plan
- Existing users updating to this version will automatically retain the default "Smack" sound without any manual migration steps.
- If a user wishes to silence the app or change the tone, they can do so directly from Settings → Panel → Sound.
