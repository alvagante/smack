# 1.1.0 release validation

## Scope

Candidate: `devel`, based on `6654fb7`, including all staged, unstaged and new files present during validation. No changes are deferred to a later release. `CHANGELOG.md` groups these changes under 1.1.0; `[Unreleased]` is empty. App metadata is 1.1.0, build 11; the baseline generator reports 1.1.0.

Local environment: Apple Silicon, Swift 6.4.2, full Xcode, macOS 27.2 SDK. This does not establish runtime compatibility on macOS 15.

## Checks

- Full serial suite: 624 tests in 16 suites passed initially (101.596 s) and again after the measurement-harness fix (99.415 s); no compiler warnings in the final run.
- Optimized dev-server budget: passed, warm 100-listener p95 0.196 ms.
- Optimized agent-session budget: passed, 1,000 processes, p50 1.238 ms, p95 1.333 ms, maximum 1.462 ms.
- App Store flavor compilation: passed.
- Workflow YAML parsing and shell script syntax: passed.
- Direct and App Store release bundles: passed; both contain all five production App Intent definitions.
- Bundle metadata and flavor isolation: passed; both report 1.1.0/build 11, only Direct contains the CLI/helper/installer, and App Store omits unsupported privacy descriptions.
- Helper installer tests: 3 passed.
- Strict bundle signature verification: passed for both ad-hoc bundles.
- DMG packaging and `hdiutil verify`: passed; `/tmp/smack-release-validation/Smack-1.1.0-validation.dmg`. This is a local validation artifact, not a signed/notarized release.

Both budget tests ran with `SMACK_PERFORMANCE_BUDGETS=1` and `SMACK_AGENT_BENCHMARK=1`. Bundles are built under `/tmp/smack-release-validation`, explicitly ad-hoc signed to avoid modifying the installed app or contacting signing services. Local logs are `/tmp/smack-*.log`; command results are also in the external agent command log.

## CI findings

- Test run `42399619990` failed because `AgentSessionDetail.networkValue` inherited main-actor isolation. Existing commit `6654fb7` makes the pure formatter nonisolated. Local suite and optimized tests compile and pass with that fix. Its remote Test run `42402097646` was cancelled, not successful.
- Historical App Store run `41921246182` used malformed workflow indentation (`steps` nested under `env`). The current workflow already corrects that structure and sets the keychain path in a step. YAML parsing passes locally.
- Fixed a remaining Swift concurrency warning in the opt-in dropped-event measurement harness: each concurrent worker creates its own `FileManager`, rather than capturing a non-Sendable instance. No production collection changes.

- Perform the release comparison required by `CONTEXT.md`: candidate versus `main`, Panel closed and open, at least ten minutes each, recording CPU, memory and wakeups. Project collection changes still have estimates, not these measurements. No running app was replaced or launched during this validation.

- Developer ID signing, notarization, stapling and Gatekeeper assessment are verified only by the actual release workflow, not by ad-hoc local packaging.
- Commit the complete candidate, confirm the merge/push, and publish `v1.1.0` only after the gates pass. No commits, pushes, tags or releases were created during this validation.
