# macOS system data and timeline research

Research date: 2026-11-12. Scope: macOS 15 and later. This is an inventory of useful sources, not a claim that every Mac contains every record. Availability depends on activity, configuration, permissions, sandboxing, and retention. Paths and formats for undocumented stores are implementation details, not contracts.

## System sources

| Source | What exists by default and how to access it | Timeline value and limits |
| --- | --- | --- |
| Unified logging | System and participating applications emit structured logs into an in-memory and compressed on-disk store, read through Console, `log`, or OSLog. Default, error, and fault messages normally persist subject to a storage quota; debug and info generally do not. Old records are purged and profiles can change behavior. Dynamic strings and complex objects are private by default. [Apple logging](https://developer.apple.com/documentation/os/logging), [levels and privacy](https://developer.apple.com/documentation/os/generating-log-messages-from-your-code) | Rich process, subsystem, category, severity, and time context, but not a complete audit or guaranteed retention period. `OSLogStore.local()` requires an admin account and `com.apple.logging.local-store` entitlement; do not assume it is available to either distribution flavor. [Apple OSLogStore](https://developer.apple.com/documentation/oslog/oslogstore/local%28%29) |
| Diagnostic reports | Console presents user and system crash `.ips`, spin `.spin`, log, and diagnostic reports, plus legacy `/private/var/log/system.log` and `/var/log/DiagnosticMessages`. Reports exist when the relevant events occur, not for every process failure. Apple distinguishes user and system reports and admin visibility. [Apple Console reports](https://support.apple.com/guide/console/cnsl664be99a/mac) | Crash, hang, and resource incident markers with a link to the original report. Preserve report occurrence time separately from file creation or discovery time. Formats, access, and retention must be tested on supported releases. |
| File system events | FSEvents supports persistent per-volume change streams, subject to event IDs and volume history availability. The stream is advisory; history can be discarded or unavailable and changes may be coalesced. [Apple FSEvents guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html), [stream UUID](https://developer.apple.com/documentation/coreservices/1444453-fseventscopyuuidfordevice) | Useful for scoped change detection and invalidating inventories, not a reliable historical per-file audit, actor attribution, or precise timestamped timeline. Respect dropped-history signals and rescan. |
| Preferences and managed configuration | UserDefaults and CFPreferences store scoped app and user preferences, often persistently; sandbox restrictions apply to access to other apps' settings. Registration defaults and volatile domains mean a plist is not the whole effective configuration. [Apple preferences](https://developer.apple.com/documentation/corefoundation/preferences-utilities), [sandbox restriction](https://developer.apple.com/documentation/foundation/userdefaults/init%28suitename%3A%29) | Current configuration, not a change history. Show selected, meaningful settings or explicit snapshot differences; do not indiscriminately collect values that may contain private data. |
| Launch and background items | Apple documents system and third-party launch agent and daemon plist locations; background item management also exposes present status via `sfltool dumpbtm`. [Apple launchd](https://support.apple.com/guide/terminal/apdc6c1077b/mac), [background task management](https://support.apple.com/guide/deployment/depdca572563/web) | Current configuration and status. An item's file modification time is not proof of installation, enablement, or launch. Only an observed state difference or an attributable log record is a timeline event. |
| Hardware, network, software inventory | System Information reports hardware, connections, OS, apps, and extensions, including some versions and modification dates. [Apple System Information](https://support.apple.com/guide/system-information/welcome/mac) | A snapshot for incident context; modification dates are not necessarily install or execution events. Installation records and app-specific log files have incomplete coverage and should be treated as separate optional sources. |
| Security events | Endpoint Security offers live security event subscriptions, including authentication, sessions, and malware-related events; Apple describes the old OpenBSM audit trail as deprecated. [Apple Endpoint Security](https://developer.apple.com/videos/play/wwdc2022/110345/) | A live subscription is not evidence of a ready-made historical event log. Entitlements, deployment, resource cost, and product scope require separate investigation; do not assume it is available by default. |

App-owned logs, databases, caches, shell history, browser data, Keychain, and application support files vary by app and user. They can contain sensitive content; existence, retention, location, and format are not uniform. They are not a safe general-purpose event feed. Explicitly selected integrations can be investigated independently.

## Smack today

- [Activity models](../../Sources/Smack/ActivityModels.swift) define existing persisted activity types. [Activity recorder](../../Sources/Smack/ActivityRecorder.swift) derives process starts and exits from snapshot differences, so the recorded time is observation time, not necessarily the actual transition time. Existing history is incomplete when collection is off or the app is not sampling.
- [Settings](../../Sources/Smack/Settings.swift) default to seven days of history, 100,000 event rows and a 2,000-event read limit; connection collection defaults off. [Timeline](../../Sources/Smack/Views/TimelineView.swift) filters loaded events in memory and limits display to 500.
- [Process inspection](../../Sources/Smack/Views/ProcessInspectionView.swift) already offers recent unified logs for a running process using `/usr/bin/log` over five minutes with a 1 MB output cap, and matching crash reports. This is distinct from a system-wide historical timeline. PID-only correlation risks reuse and cannot identify an exited instance reliably.

## Timeline preparation

1. First expose existing crash and hang reports as on-demand, bounded timeline sources and link to original details. Add targeted, filtered unified-log queries around a selected incident or process after testing access in each app flavor. Avoid presenting every default-level log as an actionable incident. Power, sleep, wake, reboot, install/update and service failure markers are candidates only after validating stable source coverage on supported versions.
2. Federate source queries on demand for a bounded time window rather than copying all logs into Smack's database. Merge sorted, paginated results; push filters and limits into each source, cancel on navigation, and cap runtime and output. Continue using Smack's own history for sampled metrics and observed events. No background watcher or new history writes by default.
3. Model occurrence time, observation time and uncertainty separately, including source, source-specific ID, severity, process identity, and original record reference. Match process instances by boot/session and PID plus start time where available; label weaker bundle, executable or name matches as inferred. Deduplicate only when source-specific evidence supports it. Correlation is not causation.
4. Display per-source coverage, permission failures, source retention gaps, query failures and truncation; distinguish unavailable, empty and not queried. Show sampling gaps and partial results. Use a stable pagination cursor or overlap and deduplicate where the underlying source permits it; do not imply an atomic cross-source snapshot.
5. Validate with fixtures for report versions, duplicate events, PID reuse, missing timestamps, ordering, permission denial, truncated output, cancellation and daylight-saving transitions. Test real access, cost and behavior on macOS 15+ in both distribution flavors. Before implementation, discuss CPU, wakeups, memory, subprocess and disk estimates, cheaper alternatives and defaults; then measure as required by [CONTEXT.md](../../CONTEXT.md).
